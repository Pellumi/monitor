Entitlement Specification (ES)
1. Purpose
This document defines all plan-based feature access, usage rights, resource limits, governance capabilities, and future intelligence capabilities within TELLANN.
The Entitlement Specification establishes:
* Feature entitlements
* Resource entitlements
* Governance entitlements
* Intelligence entitlements
* Plan enforcement rules
* Upgrade behavior
* Future entitlement evolution
This document serves as the authoritative source for all entitlement decisions across the platform.
2. Entitlement Philosophy
Entitlements determine what a customer can access.
Billing determines what a customer pays.
Usage metering determines what a customer consumes.
These concepts shall remain independent.
Example:
A customer may have access to:
* Session Replay
while consuming:
* 2 GB storage
and paying for:
* Local Plan
The entitlement system must support future platform evolution without redesign.

ES-TIER-001
A tiered entitlement shall resolve to a single level per organization, and every consumer of that entitlement shall resolve the level through one shared resolver, so that the enforcing service, the settings surface and the dashboard cannot disagree about what a customer may do.
ES-TIER-002
An unrecognized truthy tier shall degrade to the most restrictive level, never to the most permissive.

Capability Definitions
Desktop Guided Runs
Drive a demonstration run through the managed browser session. The core Phase 1 loop.
Visual & Accessibility Analysis
Findings raised during a run. BASIC covers a core rule set; higher tiers widen coverage and add remediation detail.
Browser Trace Capture
Network and interaction trace detail retained alongside evidence. BASIC retains summary trace; ADVANCED retains full request and response metadata within privacy rules.
Codebase Intelligence
Local codebase analysis and the code graph. BASIC covers analysis and checkpoint location; STANDARD adds blast radius; ADVANCED adds snapshot comparison and cross-snapshot queries.
Document Flow Inference
Drafting candidate flows from imported product documents. Bounded by the MVP Scope Document, Section 9.1.
Automated Instrumentation
Planned, reviewed and reversible instrumentation of a bound workspace. BASIC covers single-flow plans; ADVANCED covers multi-flow plans and bootstrap instrumentation.
Shared Run Governance
Shared workspace roster, branch policy enforcement across members, and time-boxed checkout grants. Requires more than one seat to be meaningful.
Priority Processing
Preferential queueing for analysis, report generation and drafting jobs.
ES-DESK-001
Where a tiered desktop capability is unavailable on a plan, the agent shall state which plan provides it rather than failing silently.
ES-DESK-002
Automated Instrumentation being unavailable shall not prevent a demonstration run. The developer instruments manually and the run proceeds.

12. Entitlement Enforcement Rules
Entitlements shall be enforced server-side.
Client-side enforcement is informational only.
Every protected operation must validate:
* Organization Plan
* Subscription Status
* Resource Limits
* Feature Entitlements
before execution.
13. Entitlement Resolution Order
When determining access:
1. Subscription Status
2. Plan Type
3. Feature Entitlement
4. Resource Availability
5. Tenant Policies
Access is denied if any validation fails.
Resource quotas warn organization administrators at 80% utilization and block new quota-consuming operations at 100%. Existing data remains readable and exportable, and customers retain billing, deletion, and upgrade access.
The Users quota counts active organization members plus unexpired invitations.
Demonstration Sessions are counted per organization and subscription billing period.
API Access means scoped programmatic access to management, reporting, graph, coverage, and export APIs. SDK ingestion credentials are separate and remain available on every plan within the plan's credential limit.

15.1 Assisted Intelligence Entitlement Position
Assisted intelligence is entitled through the capability it serves, not as a capability of its own.
Document Flow Inference is a gated, tiered entitlement because drafting flows from documents is a distinct customer capability.
Flow suggestion enrichment is not separately entitled. It is part of the Derivation Engine, which is available wherever flow declaration is available, and it is a fallback tier rather than a feature a customer chooses.
ES-AI-001
Assisted intelligence shall not be sold as a separate line item in Phase 1.
ES-AI-002
Where an assisted capability is unavailable — by entitlement or by provider outage — the underlying capability shall remain usable by hand.
ES-AI-003
Assisted consumption is metered internally for capacity and cost, and is not a customer-facing billing metric in Phase 1. Customer-facing AI metering begins in Phase 3, per the Usage Metering Specification, Section 11.
16. Success Criteria
The Entitlement System shall be considered successful when:
1. Every feature maps to a plan.
2. Every resource maps to a quota.
3. Plan upgrades automatically unlock capabilities.
4. Enterprise overrides remain supported.
5. Phase 2 capabilities can be added without redesign.
6. Phase 3 capabilities can be added without redesign.
7. Billing, usage, and authorization remain synchronized.
8. Customers clearly understand what they can access.


One additional improvement I would make for TELLANN specifically:
Create a dedicated entitlement object in the database rather than deriving permissions directly from the plan.
{
 "plan": "TEAM",
 "features": {
   "sessionReplay": true,
   "apiAccess": false,
   "workflowHealth": false
 },
 "limits": {
   "applications": 10,
   "users": 10,
   "storageGb": 100
 }
}
This gives you the ability to run promotions, beta programs, grandfathered plans, enterprise overrides, and feature rollouts without changing billing plans or authorization logic. It becomes extremely valuable once Phase 2 and Phase 3 introduce production intelligence and AI capabilities.
