SDK Specification Document (SDKS)
1. Document Overview
Purpose
The TELLANN SDK enables applications to integrate with the Self-Observing Testing System (TELLANN) for behavioral capture, telemetry collection, session replay, workflow discovery, quality intelligence generation, production monitoring, anomaly detection, and autonomous validation.
The SDK serves as the primary observation layer of the TELLANN platform and is responsible for transforming application behavior into structured telemetry that powers:
* Behavioral Graph Generation
* Session Replay
* Workflow Discovery
* Coverage Analysis
* Missing State Detection
* Endpoint Intelligence
* User Journey Intelligence
* Error Correlation
* Regression Detection
* Automated Test Generation
* Quality Intelligence
Scope
The SDK supports:
Phase 1 — Behavioral QA & Intent Platform
* Event Tracking
* Session Tracking
* Session Replay
* Workflow Observation
* State Tracking
* Flow Boundary Marking
* Run Correlation
* API Tracking
* Error Monitoring
* Behavioral Graph Generation Support
* Coverage Analysis Support
* Reconciliation Support
* Demonstration Mode
Phase 2 — Production Monitoring, Feedback & Analysis
* Production Monitoring
* User Journey Intelligence
* Database Intelligence Integration
* Error Correlation
* Workflow Health Monitoring
Phase 3 — Autonomous Behavioral Intelligence
* Behavioral Baseline Collection
* Regression Detection Support
* Test Generation Support
* Failure Simulation Support
* Anomaly Detection Support
* Remediation Verification Support
Non-Goals
The SDK shall not:
* Execute business logic
* Render UI
* Manage application state
* Store customer application data
* Modify application behavior
* Execute automated tests
* Access databases directly
* Alter API responses

5.1 Flow Boundary Interfaces
These interfaces are what make evidence scoping possible. They are normally written by the desktop agent's instrumentation, not by hand.
markFlowInitialState()
TELLANN.markFlowInitialState({
    flowId: "",
    stateName: "CART"
});


Emits FLOW_INITIAL_STATE. The platform switches evidence scope from PRE_BOUNDARY to IN_FLOW on receipt.
markFlowState()
TELLANN.markFlowState({
    flowId: "",
    stateName: "CHECKOUT"
});


Emits FLOW_STATE_REACHED.
markFlowTransition()
TELLANN.markFlowTransition({
    fromState: "CART",
    toState: "CHECKOUT",
    action: "CHECKOUT_CLICK"
});


Emits FLOW_TRANSITION.
markFlowTerminalState()
TELLANN.markFlowTerminalState({
    stateName: "ORDER_COMPLETE",
    terminalKind: "SUCCESS"
});


Emits FLOW_TERMINAL_STATE. Completes the run.
SDKS-FLOW-001
An application with no declared flows emits none of these. Its runs are scoped by platform heuristics instead, and its reports say so.
5.2 Run Correlation
During a demonstration run, the SDK attaches run context to every event so that evidence is attributable to the run that produced it.
Attached automatically where present:
runId
environmentId
agentVersion
instrumentationManifestVersion
SDKS-RUN-001
The SDK shall not assign evidence scope. Scope is assigned by the platform from boundary events, because the SDK cannot know where a flow begins.

* AES-256

Tamper Detection (Pre-Launch)
* SDK integrity validation
* Signature verification
Status
API key handling, transport encryption and payload validation are delivered. Request signing and tamper detection are specified and scheduled for completion and verification before general availability.
Until then, ingestion authenticity rests on the ingestion credential, which is scoped to one application and environment and is revocable.
