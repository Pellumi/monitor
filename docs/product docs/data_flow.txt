DATA FLOW DOCUMENT (DFD)
1. Purpose
This document defines how information moves throughout the Self-Observing Testing System (TELLANN).
The document describes:
* Data producers
* Data consumers
* Data stores
* Processing pipelines
* Data transformations
* Event lifecycles
* Inter-service data movement
* Phase-specific data flows
The objective is to ensure complete traceability of behavioral information from initial capture through quality intelligence generation.
2. Data Flow Principles
DFP-001 Event-Centric Processing
All platform operations originate from captured events.
DFP-002 Immutable Event History
Captured events are never modified after ingestion.
Transformations produce derived datasets.
DFP-003 Stream-First Processing
Behavioral data flows through streaming pipelines before persistence.
DFP-004 Traceability
Every derived artifact must be traceable back to source events.
DFP-005 Session Correlation
All behavioral data should be associated with sessions whenever possible.
DFP-006 Tenant Isolation
Data flows must remain isolated per tenant.

4. Primary Data Sources
Source 0 — Declared Intent
Produced By:
A human, in the dashboard or the desktop agent.
Examples:
* Declared flows
* Declared states and transitions
* Accepted suggestions
* Promoted observations
Defined by FR-123 through FR-140b.
Unlike every other source in this document, this one is not derived from anything. It is an assertion, and it is the only input the platform treats as a statement of intent rather than a record of fact.
Source 0a — Local Codebase Projections
Produced By:
Desktop agent codebase analysis.
Examples:
* Code graph topology
* Flow checkpoint locations
* Analysis warnings
Source content remains on the developer's machine. Only projections enter the platform.
Source 0b — Customer Documents
Produced By:
Customer upload through the desktop agent.
Examples:
* Product specifications
* Requirement documents
Processed into source document versions, then into intent drafts for human review.
Source A — Frontend Events
Produced By:
Frontend SDK
Examples:
* Page views
* Route transitions
* Clicks
* Form interactions
* Form submissions
* UI events
* Errors
Defined by FR-001 through FR-010.
Source B — Backend Events
Produced By:
Backend SDK
Examples:
* API requests
* API responses
* Response times
* Exceptions
* Endpoint metrics
Defined by FR-011 through FR-017.
Source C — Production Monitoring Events
Produced By:
Production Monitoring Services
Examples:
* Live user sessions
* Workflow health events
* Production telemetry
Defined by FR-066 through FR-069.
Source D — Database Telemetry
Produced By:
Database Intelligence Collectors
Examples:
* Query execution metrics
* Query duration
* Index utilization
* Field utilization
Defined by FR-081 through FR-085.
