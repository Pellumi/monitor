# Quickstart

Connect an application and confirm your first behavioral event in about five minutes.

## Before you begin

Before working with **Quickstart**, identify the organization, application, environment, plan, and role that own the change. Use a non-production environment for initial verification whenever the task can affect telemetry or access.

## Procedure

Follow the task in order and preserve the boundary between public application configuration and secret material. Make one scoped change, record its visible result, then continue to the next step.

## Verify the result

Verify the nearest authoritative signal: SDK diagnostics for capture, an accepted event for ingestion, a session timeline for correlation, a graph or report for processing, and an audit record for administrative mutations.

## Expected result

The task is complete when the intended Tellann object or behavior exists in the correct scope and a second reader can identify how it was verified. A successful button click without persisted evidence is not completion.

## Common errors

If verification fails, check permissions, entitlement, environment selection, credential scope, network destination, and processing status. Correct the earliest failing boundary before repeating downstream actions.

## Next steps

Continue to the related concept or reference page to understand the resulting data, then use the relevant troubleshooting runbook if the verification signal remains absent.

### Minimal frontend setup

```ts
import { initialize, trackEvent } from '@tellann/frontend-sdk';

initialize({ apiKey: process.env.NEXT_PUBLIC_TELLANN_INGESTION_KEY });
trackEvent('QUICKSTART_VERIFIED', { source: 'docs' });
```

> [!TIP]
> Keep the ingestion key in environment configuration and confirm the event in the intended non-production environment before adding automatic tracking.
