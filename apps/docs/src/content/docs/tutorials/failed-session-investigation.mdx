# Failed Session Investigation

Learn how failed session investigation works within Tutorials and how to apply it safely in Tellann.

## Goal

Use this tutorial to complete **Failed Session Investigation** as a coherent Tellann scenario. The goal is to produce evidence you can inspect, not merely to reach a screen without errors.

## Starting state

Begin with an organization, application, environment, and active ingestion key. Confirm the SDK reports a connected state before collecting the scenario; keep production credentials out of examples and local history.

## Complete scenario

Run the scenario from its first meaningful state through the expected success or failure boundary. Name the workflow, capture relevant UI, state, API, and error events, then allow processing to finish before interpreting coverage.

## Expected artifacts

A successful run leaves a session timeline, workflow activity, graph states and transitions, and any applicable coverage or endpoint findings. Reports should link back to the evidence that supports each conclusion.

## Verify the result

Open the resulting session and check event order, environment, workflow label, state transitions, and error or endpoint correlation. A rendered graph alone is not sufficient if its source events are missing or out of order.

## Cleanup and next steps

Remove tutorial-only keys and test data when they are no longer needed. Continue with the related concept, integration, or troubleshooting page for the weakest verification signal.
